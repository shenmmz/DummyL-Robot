## 2 真机铁律
- 唯一标准是**读回来的实际值**；"命令没报错"不算。顺序 `enable`→`getpos`→`alarm`。
- 不 enable 时 getpos 是假数；失联时 getpos 打 `0,0,90,0,0,0` 假数 ⇒ 用 `alarm` 交叉验证；报"部分关节无响应"⇒ **禁止下发运动**。
- `alarm` 读 `0x00A3`(低4位=当前，高12位=最近三次)，`:clear` 写 `0x00A4=0`。报警未清 ⇒ 状态字 bit21=1 ⇒ "已退出 RUN"永不成立 ⇒ 运动超时。
- **到位判据只有一份**：无报警 + 已退出 RUN + 位置在 target±tol 内。`STAT_INPOS`(bit12) 是**粘滞位**，只看它必假阳性(实测差 28.5° 也报"到位")。
- 报警现状：J5 当前=电机相位过流；J1/J2/J3/J5 历史=供电电压过低。J5"一动就过流"未查清。

## 3 ★★ 总线读法修复(2026-09-23，最大性能修正)
**根因**：`read_frame(rx,300,50)` 的 **ReadFile 请求字节数 > 实际到达字节数 ⇒ 不会因"读满"完成**，只能等 `ReadIntervalTimeout`；CH341SER 挂在 **~15.6ms 节拍**(=Win 64Hz 定时器) ⇒ 每笔白等一节拍。与波特率/USB/驱动器无关。
判据：`cap=300→15.37ms`｜**`cap=9(正好一帧)→1.70ms`**｜`cap=10→15.17`｜`cap=64→15.44`。
**修法**：`modbus_read_reply()` 分三段精确读。读类 `2→1(字节数)→n+2`；写类 `2→6`；异常 `2→1→2`。
**作废别引用**：~~T_usb 10.35~11.35ms 占 67~74%~~、~~换 FTDI/CP210x~~、~~提波特率收益仅一成~~、~~单事务 15.4ms~~、~~noread 3.3 倍~~。
**新基线(921600)**：单事务 **1.70ms**(read 1.63)｜一轮六轴 **10.2ms ⇒ 97.9Hz**｜`busrate[1]` 1.70ms/588Hz｜`busrate[3]` 只写不等 0.15ms。旧值 15.60 / 93.6ms→10.7Hz。
- 拆解：1.74 ≈ 0.087(请求线上)+T_drv(1.4~1.9)+0.14(响应线上)+USB(≤0.08) ⇒ **86% 在等驱动器应答**；换工具/再提波特率只剩约 13%。
- **换转换器唯一判据 = `diag` 的 read 段**(应≈1.6ms；仍 15ms ⇒ 读法退化，不是转换器问题)。`diag` 的 write 0.08ms 不是真实发送耗时，别与 `busrate[3]` 混用。
- ⚠️ **noread 会留下没人读走的回帧**，被下一读当应答 ⇒ CRC 失败。症状：同一命令行 `diag` 后紧跟 `busrate`，busrate 首笔读报"关节1 不在线"(分两次启动进程反而正常)。⇒ 已加 `bus_drain()`(`Sleep(20)` 后 `flush()`，**顺序不能反**)，`diag`/`busrate`/`nrtest` 首尾各调一次。
- **串口不是 ini 写死**：`main.c` 枚举 `HARDWARE\DEVICEMAP\SERIALCOMM` 并**覆盖** ini。0个⇒报错退出；1个⇒直接用；多个⇒让用户选。换工具不改 ini 但**必须重启程序**。
- CH340 无 LatencyTimer(那是 FTDI)。总线锁在 `robot.c` 的 `robot_request`/`_noread`，新快路径**必须持锁**(坑：`motor_write_i32_noread` 绕过锁 ⇒ diag 刷假掉线)。批量/流水线用 `robot_bus_lock()/unlock()`。
- **`robot_init` 只要求串口能打开**，六轴全离线也不退出 ⇒ 不接机械臂也能跑 looptest。程序须在**项目根目录**跑(`INI_PATH` 相对路径)。

## 4 驱动器波特率 0x0009(手册 §6)
低 8 位=档位码；bit9~8 校验(0无/1偶/3奇)；bit11~10 停止位。出厂 12。档位 1=300 … 11=57600 **12=115200 13=230400 14=460800 15=921600**。**没有 256000**(手册第二章"速率-距离"表是物理层模板，不是档位；§6 值域 1~15 已排满)。
- ⚠️ 写完**立即生效** ⇒ PC 侧不同时改就**当场失联**；6 台必须**广播一起写**。⚠️ 不固化则断电回 115200 而 ini 已是新速率 ⇒ 下次上电失联 ⇒ **必须 `0x00DC=1` 固化**；但它把**所有**带记忆的 RAM 值(含 ACC/DEC)一起写进 Flash，先调好再固化，**写 0 是恢复出厂**。
- `drvbaud`：只读 / `:CODE` 广播写(写完即失联) / `:CODE:BAUD` 写+切PC侧+回读(**推荐**) / `:save` 固化。
- 现状：六轴全档位 15=921600(已固化)，固件 21.9，`ini baudrate=921600`。固化把 ACC/DEC 30/30 一起写进 Flash。
- 收益 **1.93 倍**(50.8→97.9Hz，同会话切回 115200 实测)。⚠️ **读法没修前这收益被完全掩盖** ⇒ 复测必须先修读法。

## 5 movel「直 vs 顺」不可兼得
- 根因(手册 66 节⑤)：运行时收到新绝对目标**立即执行、当前指令强行结束** ⇒ 每段末独立加减速、**速度归零**。避不开。段数 N = 归零次数 N，单次归零 = ACC+DEC = 80+90 = 170ms。
- 卡顿模型 `额外耗时 = 固定收尾 0.32s + 段间停顿次数×每次停顿`(过流开 0.48s / 关 0.335s)。比值不能跨线长比较。⚠️ **待复核**：在"轮询 92ms"下拟合的，修读法后轮询 10.2ms ⇒ 0.32s 里约 80ms 是轮询延迟，别沿用。
- **弓高 ≈ 0.001×段长²(mm)**；`段数 = ceil(sqrt(整段弓高/bow_mm))`；L mm 内不分段：`bow_mm = 0.001×L²`(20⇒0.4/30⇒0.9/50⇒2.5/80⇒6.4/100⇒10)。
- 模式：`sync`(按 bow_mm 分段+逐航点等到位)/`step`(1mm 弦)/`stream`(不等+每节拍重设速度)/`smooth`(1 段)。语法 `movel X,Y,Z[,Rx,Ry,Rz] [SPD,ACC,DEC] [keep][,模式]`。
- **默认已改 `smooth`**(用户拍板)。代价①走关节空间直线(弓高=整段)②**全程不查过流** ⇒ 碰撞保护须显式 `,sync`。

## 6 ACC/DEC
`0x0096/97` 启停速度 50rpm；`0x0098/99` 加速/减速时间(0~65535)。实测六轴：启 0/停 0/加速 **80**/减速 **90**ms。`accel[:ACC[,DEC]]`，无参只读。只写 RAM 不发 `0x00DC` ⇒ 断电恢复。⚠️ 别发 `0x00DC=1`。太小丢步/过流，从 40 起试。

## 7 RS485 工具
- ⚠️ **旧"驱动器侧耗时 = 15.4 − 回环RTT"公式作废**(那 15.4 里 13.6ms 是 `cap=300` 的节拍等待)。当年没看出来：looptest 用**精确长度**读、`modbus_transact` 用 `cap=300` ⇒ 两边等待量不同，减法把噪声当结论。**教训：A/B 两侧必须用同一种读法。**
- `looptest[:N[:BAUD[:AUX]]]`。`[2]` 连发推帧 = **1.12ms/帧≈892Hz** ⇒ 写方向没问题。
- **物理事实**：同端口 A-B 短接 ⇒ 差分恒 0 ⇒ 一字节收不到；回环要求 A/B **悬空**。本机 CH340 单模块发时关收 ⇒ **测不出 RTT**，只能上双模块(**A-A/B-B 对接+共地**，短线 <1m 不加 120Ω)。⚠️ 命令自动恢复波特率/RTS；RTS 停在 ENABLE 会让六轴全"离线"。术语坑：用户说"A 与 B 接一起"指**标准多点总线**，不是同端口短接。
- `nrtest`：安全帧间隔 **2ms**(0ms 撞车)。**noread 已无优势**(`6×(0.15+2)≈13ms` 比等响应 10.2ms 更慢且无确认) ⇒ ini `[movel] noread_gap_ms` 保持 0 是对的；`MOVEJ_NR_GAP_MS`(=4) 是死代码。
- `bcast`：10H 广播写 `0x00D8` 六轴全执行 ⇒ **广播有效**。
- `pipe[:轮数[:间隔us]]`(新探针，只读不动臂)：先连发 6 请求再收 6 响应、按从站地址解复用。扫 `{0,50,100,200,300,500,1000,2000}us`；判据 **某档丢帧=0 且快于基线 ⇒ 可行**。nrtest 只取 0/1/2/3/5ms 点，**0.1~1ms 细粒度是空白** —— pipe 就是填这个。
- ⚠️ **`tabtest` 会动臂**(写 3 段相对位移表+`0x00DD=0x8001` 让驱动器自己走)，**别归进"只读"**。⚠️ **`looptest` 会改波特率与 RTS** ⇒ 跑它期间驱动器收到的全是垃圾帧、看起来"六轴全掉线"；有自动恢复，但**跑完必须敲一次 `getpos` 确认还在线**。

## 9 cmd_parse 坑(已修)
非法参数打警告后**命令照样执行**(`busrate:7` 跑了一整遍)。根因：分支**先设 `out->type` 再校验**，失败 `return CMD_UNKNOWN`，但 `main.c` **只看 `cmd->type` 不看返回值**。修法：入口 `memset(out,0,...)` + 46 处先复位 type 再返回。`line==NULL||out==NULL` 那处**不能**写 `out->type`。**新增命令：`out->type` 要么放全部校验之后，要么保证失败时复位。**

## 11 机械原点与标定
每关节小凹槽，**人工对齐 = 机械原点**，应显示 `0,0,90,0,0,0`。q0 正确来源 = 对齐凹槽→读编码器→反算零点。跑 `home` 是堵转清零 ⇒ 读数**必然是定义值、零信息量**。判零点先问"用什么外部参照判定的"。凹槽粗标 ±0.5~1°；J5 差 1° ⇒ 笔尖偏 0.72mm。
堵转阈值疑似偏低：静止电流 ~500/499/495/385/371/254mA vs 阈值 480/490/480/400/390 ⇒ J1/J2/J3 一上电就"已堵转"。未证实。

## 12 movel 姿态参数 = "画斜线"头号根因
`end_pose` 全取用户输入、起点由 FK 得；姿态不一致 ⇒ SLERP 拧姿态 ⇒ 笔尖绕法兰摆 `tool_length×sin(θ)`。80mm 线实测：抄 getpos 原值 ⇒ **0.0000mm**；抄 home 的 `115,90,115` ⇒ **7.71mm**。法兰直线度恒 0.0000mm ⇒ **只看法兰坐标永远发现不了**。
**必须抄【当前 getpos】原值，含负号、含 -0.00**。防护 `movl_pose_warn()`(ini `[movel] tip_warn_deg` 默认 5°)；离线自查 `build/bin/movl_tip_trace.exe`。
法兰法线：home 水平(q2+q3+q5=90)，绘图位姿竖直向下(=180)。getpos 拿"法线应竖直"当通用标准 ⇒ **对 home 是误报**(用户 2026-09-21 确认)，未获确认前不动 getpos。

## 15 ★ 读法修复后新冒出来的瓶颈
**架构结论(2026-09-23 评审)：`src/` 不用重建。** 总线锁/事务都在最底两层，`robot.h` 公开 API 全是单轴 ⇒ 加批量读只需在 `robot.c` 加 `robot_read_positions_deg()`，**kinematics/trajectory/cli 一行不动**；换 CAN/EtherCAT、加 6 路总线同理。**瓶颈被分层关在最底层，正说明分层对了。**
**① 11 处 320ms 盲等 → 事件握手(已改)**：旧写法 `monitor_pause_active(1); Sleep(MONITOR_DEFAULT_INTERVAL_MS+20);` 必须盲等是因为 `monitor_thread_main` 是 `poll→Sleep(interval)` 循环、`paused` 只在下一轮开头才看到；修复后巡检只 20ms ⇒ **那 320ms 里 300ms 是纯睡**，每次 MoveJ/MoveL 都付一次。新机制：`monitor.c` 加 `parked`+`wake_ev`+`parked_ev`，线程用 `WaitForSingleObject(wake_ev,interval)` 代替 `Sleep`；新增 **`monitor_park()`**(=pause+等停住，drop-in)与 `monitor_park_wait(timeout)`(1=停住/0=超时打警告后按旧行为继续)，超时 500ms ⇒ **兜底等同旧行为，零回归**。⚠️ `monitor_start` 现在复位 `paused=0`/`parked=0` —— 否则 `home` 的 `stop→start` 若残留 paused=1，监控永久停摆；恢复仍用 `monitor_pause_active(0)`(11 处含提前 return)，**未改**。**已真机验证通过(2026-09-23，COM4@921600，六轴全在线)**：同一次会话连敲两次 `diag`(间隔 5s) ⇒ 第 1 次印 `后台巡检停住 20.38 ms`／`后台巡检累计 1 轮`，第 2 次印 `0.01 ms`／`累计 15 轮`。20.38ms 正好 = 「等巡检跑完当前一轮」(12 笔 × 1.70ms ≈ 20.4ms)，监控在睡时几乎立刻返回(0.01ms) ⇒ 旧版固定盲等 320ms，**最坏快 15.7 倍、最好快 32000 倍**；`累计` 1→15 与「周期 = 巡检 20ms + interval 300ms」吻合 ⇒ 监控未被挂起。
**② `cmd_diag` 采样 N 30→10(已改)**：实测 20 轮最快 10.16/最慢 10.70/中位 10.21/均值 10.28 ⇒ σ_单事务≈0.053ms；SEM N=10→±1.0%、N=5→±1.4%，判据阈值 5% ⇒ **N=10 有 5 倍余量**。diag 总时长 314→**277ms**。⚠️ 只改了 `cmd_diag`，**`cmd_busrate` 仍是 30**。
