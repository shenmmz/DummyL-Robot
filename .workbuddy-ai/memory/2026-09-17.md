# 2026-09-17

## 控制台输出降噪（src/cli/commands.c）

用户反馈："把不该打印的东西关掉或者删除掉"。做了 5 处：

1. **删掉"本段实测最大偏差"逐段打印**（step 模式 50 段会刷屏 50 行）。
   改为文件内累加器 `g_dev_peak / g_dev_seen` + `dev_reset()` / `dev_report(tag)`，
   由 `cmd_movel` 在整条 MoveL 结束时汇总一行：`实测最大偏差 X mm（全程峰值）`。
   sync / step / stream 三条出参路径分别调用 `dev_report("sync ")` 等。

2. **修掉 `偏差 0.00mmmm` 重复单位**。根因：`\r` 覆盖时新行比旧行短
   （`spd` 从 `-17` 变 `0` 短 2 字符），行尾残留上一轮的 `mm`。
   新增 `status_line()`（vsnprintf 到 buf，按 `MOVEJ_STATUS_W=78` 定宽左对齐输出）
   和 `status_clear()`（`\r%78s\r`），所有 `\r` 刷新统一走这两个函数。

3. **提示去重**：`[提示] 段时长短于加减速之和` 按 (段时长, ACC+DEC) 去重；
   `[提示] 节拍超段时长 25%` 与 `[提示] 单事务偏慢(Latency Timer)` 改为
   进程内 static 标志，只出现一次。连画正方形四条边不再被同一句话提醒四遍。

4. **stream 尾部诊断块压缩**：`下发实测：每节拍…` + `节拍占段时长…` 合成一行；
   `MoveL stream %d/%d 段完成` 去掉重复的 `count-1` 参数。

5. **轮询从 13 事务降到 6 事务**（附带的性能修复，不只是打印）：
   原来每个轮询 = `robot_read_position_deg`×6（显示）+ `motor_read_position`×6（到位判定）
   + `motor_read_speed`×1（显示 spd）= 13 个 Modbus 事务 ≈ 340 ms/轮。
   现在只读一次六轴位置（同一个 LEESN_REG_POS），既做到位判定也算末端偏差；
   `spd=` 字段直接删掉（每轮多花一个事务却只有 J1 一路速度）。
   轮询周期 ≈160 ms，step 模式每段开销、以及结束前的到位等待都约减半。

注意：`status_line` 用到 `va_list`，已在 commands.c 顶部补 `#include <stdarg.h>`。
超时急停分支开头加了 `status_clear()`，避免警告接在 `\r` 行后面。
