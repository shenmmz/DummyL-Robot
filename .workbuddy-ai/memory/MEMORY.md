## 1 铁律
- 唯一标准是**读回来的实际值**。顺序 `enable`→`getpos`→`alarm`。失联时 getpos 打假数 `0,0,90,0,0,0`；报"部分关节无响应"⇒**禁止下发运动**。
- **到位判据只有一份** = 无报警 + 已退出 RUN + 位置在 target±tol。`STAT_INPOS`(bit12) 是**粘滞位**，只看它必假阳性（实测差 28.5° 也报"到位"）。
- **改完代码必须在同一条回复给验证方法**：复现步骤（含"必须重启程序"这类前置）+ 看哪几行 + 每行应为多少。要数据就给原始数据，别顺带造脚本/文档。
- CLI **单线程**（`main.c` 一个 `fgets`→dispatch 循环）⇒ 命令天然串行；唯一并发者 = 后台监控线程。程序须在**项目根目录**跑。

## 2 ★★ 总线读法修复（2026-09-23，最大一次性能修正）
**根因**：`ReadFile` 请求字节数 > 实际到达字节数 ⇒ 不会因"读满"完成，只能等 `ReadIntervalTimeout`；CH341SER 挂在 **~15.6ms 节拍**（Windows 64Hz 定时器）。**修法**：`modbus_read_reply()` 分段精确读（读类 `2→1→n+2`／写类 `2→6`／异常 `2→1→2`）。
**新基线(921600)**：单事务 **1.70ms**｜一轮六轴 **10.2ms ⇒ 98Hz**。拆解 = 线上 0.23 + **驱动器周转 1.47（86%）** + USB ≤0.08。
⇒ **等响应下界 10.20ms，实测 10.28 ⇒ 已用掉 99%，到顶**。`noread` 零收益。唯一零硬件出路 = **流水线**（理论 2.84ms/352Hz，用 `pipe` 实测）。
⚠️ 换转换器的唯一判据 = `diag` 的 read 段（应 ≈1.6ms）；仍 15ms ⇒ 是读法退化，不是转换器。

## 3 三条最贵的坑
- **原点**：每关节小凹槽，**人工对齐 = 机械原点**，应显示 `0,0,90,0,0,0`。跑 `home` 是堵转清零 ⇒ 读数**必然是定义值、零信息量**。
- **movel 姿态参数 = "画斜线"头号根因**：`end_pose` 必须抄**【当前 getpos】原值**（含负号、含 `-0.00`）。80mm 线实测：抄 getpos ⇒ **0.0000mm**；抄 home 的 `115,90,115` ⇒ **7.71mm**。法兰直线度恒 0.0000mm ⇒ **只看法兰坐标永远发现不了**。
- **movel「直 vs 顺」不可兼得**（手册 66 节⑤）：运行时收到新绝对目标**立即执行、强行结束当前指令** ⇒ 每段末速度归零（一次归零 = ACC+DEC = 170ms）。弓高 ≈ `0.001×段长²`(mm)。默认已改 `smooth`（走关节空间直线、**全程不查过流**）⇒ 碰撞保护须显式 `,sync`。
