# DummyL-Robot 长期项目约定

## 用户对画直线的实际精度需求（2026-09-18 亲口确认）

**用户原话："之前我默认使用 sync 模式都不会画弧啊"** —— 指的是改成"逐航点等到位"
**之前**的那个 sync（定时注入版）。而那一版实测偏差 1.77mm ≈ 整段弓高 2.08mm，
**本来就是在画弧**，只是 2mm 在 50mm 线上视觉上看不出来。

⇒ **用户实际可接受约 2mm/50mm 的弓高**（约 4%），远宽于默认预算 0.10mm。
⇒ 现在的 smooth 模式 ≈ 用户之前习惯的观感。

**50mm 线的档位**（弓高 ∝ 段长²）：
| 预算 | 段数 | 弓高 | 卡顿 |
|---|---|---|---|
| smooth（1段） | 1 | ~2.0mm | 无（= 用户之前的体验） |
| 2.0mm | 2~3 | ~0.5mm | 很轻 |
| 0.5mm | 3 | ~0.23mm | 中 |
| 0.10mm（默认） | 5~10 | ≤0.10mm | 明显一顿一顿 |

**决定性旁证（用户 2026-09-18）**："跑 movej 很流畅，跑 movel 就一卡一卡"。
movej 是**单段**：一次下发、六轴按行程比例配速、驱动器各自梯形规划同时到达，
只有 1 次启动、无段间停顿。movel 分段后每段都要"减速到 0 → 下发 90ms 空档 →
重新加速"，且每段重复一次六轴启动差扭曲。
⇒ **流畅 = 单段交给驱动器规划**，这跟 Hg_Robot_Arm 的结论完全一致。
⇒ `smooth` 模式本质就是"会画直线的 movej"（代价是弧）。

**实测 4.55mm vs 几何弓高预测 0.39mm（差 11.6 倍）**：预测只算几何弓高，
漏了六轴启动差（首末轴相隔约 75ms）。启动差扭曲才是大头，且**段数越多扭曲次数越多**
⇒ 再细分不会更直，反而更糟。已把打印改成"几何弓高 ≤"并在实测超预测 3 倍时点破。

**已落地**：用户随后明确"弧小都比你一卡一卡的好" ⇒ 默认值已从 0.10 上调到 **0.50**
（`robot_config.ini` 的 `bow_mm` + 代码宏 `MOVL_SYNC_BOW_MM` 同步改，ini 优先）。
50mm 线由 5~10 段降到约 3 段，段间停顿次数减半以上，弓高约 0.23mm（看不出）。
**教训**：别拿实验室精度（0.1mm）当默认值去折磨实际使用——先问用户能接受什么。

## 总线事实（实测，勿再推算）

- 单事务 15.06 ms，其中等响应 14.85 ms（占 98.6%）；flush+write 仅 1.05 ms
- 一轮六轴 92.8 ms ⇒ 10.8 Hz；转换器吞吐只用了 12%（66 / 549）
- **连读六轴无批处理效应**：实测一轮 92.83 ≈ 推算 90.36（差 2.7%）⇒
  打包多寄存器读不会提速，瓶颈是"每笔都要等一次响应上行"，不是帧数
- 读写事务天花板 79 Hz（线上 1.82 ms + 3.5 字符间隔）
- **只写不等响应上界 159 Hz**——真实收益 14.7 倍（旧值 4.8 倍是被巡检污染的）
- CH340（VID_1A86&PID_7523）注册表**没有** LatencyTimer 项，
  "设备管理器改延迟计时器"这条路对本机不成立（那是 FTDI 的做法）
- 提速唯一现实路径：6 路独立 USB-RS485 + 只写不等响应（半双工下
  单总线不能背靠背写，noread 只在每总线单从站时安全）

## 线程模型与总线锁

- 串口是全局单例，后台巡检线程与主线程共用
- **总线锁在 `robot.c` 的 `robot_request` / `robot_request_noread`**，
  半双工下任何发送都必须持锁，与是否等响应无关
- 历史坑：`motor_write_i32_noread` 曾绕过锁，其 flush(PurgeComm) 冲掉
  巡检已收到的响应 ⇒ diag 刷假掉线。新增"快路径"务必检查是否绕过串行化
- `monitor_pause_active`：diag 已接；**运动路径（movej/movel）未接**，
  属安全取舍（挂起会丢失运动中堵转/报警监控），未获用户确认前不要擅自接

## 构建环境（每次都会踩）

1. PATH 里的 ARM 工具链会让 CMake 抓到 `arm-none-eabi-ar` ⇒ 链接全挂。
   命令行传 `-DCMAKE_AR=` 无效，必须先剔除 ARM 路径再 configure
2. `tools/replay/replay.c` 已丢失，configure 必须带 `-DBUILD_REPLAY=OFF`
3. exe 被正在运行的控制台占用时报 `Permission denied`：
   `mv build/bin/dummyrobot.exe build/bin/dummyrobot_prev.exe` 再 ninja 可绕过
4. 编译器 `C:/Qt/Tools/mingw1310_64/bin/gcc.exe`

## 其他

- 用户面角度一律**机械角**；`forward_deg[j] = 目标机械角 + q0[j]`
- 串口 COM4 @ 115200（ini），不带参数启动会读 ini
- 0x0066 = 驱动器基地址（出厂 1）。实测 J1/J2/J3 读回均为 1，但通信地址
  确为 2/3（有应答）⇒ 地址不由 0x0066 决定，疑似 0x0067 地址源走硬件
