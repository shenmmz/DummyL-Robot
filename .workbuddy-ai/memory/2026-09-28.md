## 已修：MSVC 构建四连坑（2026-09-28，为了能编出 d6=91.5 的 exe）

按顺序撞了四个，全修完构建 0 error：

1. **MSB6001**「已添加项。字典中的关键字: HTTP_PROXY / http_proxy」—— 环境同时有大小写两份代理变量，
   `ProcessStartInfo.get_EnvironmentVariables()` 键冲突。修法：`env -u http_proxy -u https_proxy cmake --build build --config Debug`。
2. **D8021**「无效的数值参数 /Wextra」—— GCC 专有开关，MSVC 不认（`-Wall` 会被当 `/Wall`，噪音极大）。
   修法：CMakeLists 加 `if(MSVC) set(WARN_FLAGS /W3) else() set(WARN_FLAGS -Wall -Wextra) endif()`，
   17 处 `-Wall -Wextra)` → `${WARN_FLAGS})`（replace_all 一次搞定）。
3. **C4819 + C2001**「字符串字面量中的换行符」—— 源码 UTF-8 无 BOM，MSVC 按 GBK(936) 解码中文，
   `ik.c:92 return "超可达";` 的结束引号被吞。修法：`add_compile_options(/utf-8)`（仅 MSVC 分支）。
4. **LNK2019** 无法解析 `strtok_r` —— POSIX 专有；因为没声明还连带一堆 C4047「char* 与 int 间接级别不同」。
   修法：`src/utils/cmd_parser.c` 顶部 `#ifdef _MSC_VER / #define strtok_r strtok_s / #endif`（MSVC 的
   `strtok_s(char*,const char*,char**)` 与 `strtok_r` 签名完全一致）。

## ⑮ 澄清"建模方式"的范式差异（18:32）
